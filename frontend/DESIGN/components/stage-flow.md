## 使用时机

`NvScreenStageFlow` 展示按宿主顺序排列的阶段数量和显式状态。它保留来源的行内分布、名称、数值与轻量连接符，适合大屏面板中的进展摘要。它不表示可点击步骤或完成比例；流程导航使用既有 Steps，单个状态使用 `NvScreenStatusTag`。

## 变体选择

使用 `stages` 的稳定 `key` 标识来源，名称可以重复。每项 `label` 和 `value` 由宿主提供；可选 `status` 的标签与色调必须显式输入。连接符默认 `›`，可替换或传空串隐藏，仅在相邻阶段之间展示。

## 规则与判定

组件只格式化有限 number，最多三位小数，保留 0、负数及小数；不修改原值。缺失、null、NaN、无穷值及不合法运行时输入显示 `—`。不解析字符串数量，不计算段间差值、WIP、瓶颈或完成状态。

默认 flex 水平分布，窄容器换行，长名称与状态全文折行。沿用来源名称 12.5px、数量 16px、连接符 15px 的内联原视距；状态复用现有 `NvScreenStatusTag`。样式使用 `nv-scr-*`、既有 token 和 `nv-components` 层，不创建字体或 token 框架。容器用 `role="group"`，宿主通过 `aria-label` 或 `aria-labelledby` 命名；只读内容不增加假按钮或焦点。

## 正例与反例

正例：阅读活动宿主输入报名、资料准备、到场数量，未知到场数传 null；状态“等待确认”由宿主明确提供。反例：根据数量递减自动判断瓶颈，或把未知数量转换为 0。
