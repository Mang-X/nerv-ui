# 设计哲学

NvUI 是一套**多形态 Vue 组件库**——目标读者是每天长时间使用界面的真实用户。它的美学不是装饰，而是为了让人**更快、更准、更少出错**地完成操作。以下原则按优先级排列，冲突时上位者胜。

## 1. 产品优先

> 产品 / UX / 用户视角 **>** 行业惯例 **>** 工程实现便利。

先问"对使用的人最好的形态是什么"，再考虑惯例与工程可行性。**不要被现成组件限制**——当既有组件不足以表达正确的产品形态时，大胆造新件，而不是把体验迁就到组件能力上。

设计与评审时使用**真实感的示例数据**（真实的名称、编号、状态与边界密度），而不是 `Lorem ipsum` 或 `占位文本`——只有看到接近真实的密度与边界，才能判断设计是否成立。

## 2. 引导，而非说明书

界面靠**结构、层级、状态与微交互**来引导操作，而不是靠成段的解说文字。

- 不要把页面写成"使用手册"。能用布局和视觉表达的，就不要用整段文字解释。
- 展示**真实可读的标识**——有含义的编号、状态、标签——而不是 `编号占位` 这类提示。标识本身就是信息。
- 空状态、错误、加载都是设计的一部分，用引导性的下一步动作代替"暂无数据"。

## 3. 原版零改动，定制靠复制重建

底层上游原语的**原版组件一律不改**，只作为组件库内部基座。应用与文档示例统一使用库导出的 Pro / Mobile 组件，再叠加设计令牌。

- 永远通过 `@nerv-ui/ui` / `@nerv-ui/ui-mobile` 的稳定导出边界使用组件，**不从上游原始包或组件深层路径导入**。
- 新组件命名不与 `@nerv-ui/ui` 既有导出冲突。
- 这样原版可随上游升级，定制层独立演进，互不污染。

## 4. 暗色主题 · 动态色 · 亮暗自适应

视觉基准是**深色**（长时间注视更护眼），同时完整支持亮色。品牌强调色是**运行时可切换的动态色**（写入 `--nv-brand`），一套语义令牌驱动全部表面，详见[设计令牌](/foundations/tokens)与[色彩](/foundations/color)。

## 5. 克制的质感

动效与质感服务于反馈与连续性，不喧宾夺主：

- 过渡用统一的缓动令牌（`--nv-ease-out-quart / expo / in-out-quart`）。
- 拖拽类交互要有**跟手 + 橡皮筋阻尼 + 回弹**的真实手感（侧滑、抽屉、下拉刷新共用同一条阻尼曲线）。
- 覆盖层（弹窗 / 抽屉 / 菜单 / Tooltip）带克制的玻璃质感（半透明 + backdrop-blur），不过分。

## 6. 四形态一致，但各自原生

桌面、移动、触屏、大屏共享**同一套设计语言**，但各自遵循平台的原生手感与触控基线——桌面键鼠紧凑（36–40px）；移动有安全区、≥44px 触控、手势；触屏大触控（56–72px）、减少操作路径；大屏远读、几乎不触控。令牌按场景命名空间隔离（`--nv-*` / `--nv-m-*` / `--nv-t-*` / `--nv-scr-*`），一件组件跨形态时拆两件实现，不"一件双态"。详见[四种形态](/guide/surfaces)与[设计令牌](/foundations/tokens)。
